# Implementation Plan: Skill Mastery Analytics

**Branch**: `001-skill-mastery-analytics` | **Date**: 2026-10-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-skill-mastery-analytics/spec.md`

## Summary

Compute, on read, a per-student mastery map (subject → unit/lesson → earned/attempted
points), by joining the per-question `Detailed Review JSON` recorded in `Submissions`
with the subject/unit metadata in `Question_Bank` — no new tag data, no new sheet, no
new engine. Expose it behind the existing typed-token gateway as new server RPCs
(`getMasteryReport`, `createUnitPracticeExam`) and surface it in the student portal
and Parent Portal, including a top-3 weakest-units list and unit-targeted practice
generated through the existing exam factory with the same refusal rules.

## Technical Context

**Language/Version**: Google Apps Script (V8 server-side JS in `Code.gs`); browser JS
in template HTML files (ES+/HTML service); Python 3 (tooling, E2E harness, bundler);
Node.js 20+ for server unit tests.

**Primary Dependencies**: Google Sheets as the only durable store; `HtmlService`
templates with `include()`; `LockService` for submission writes; `CacheService` for
tokens/PIN rate-limiting only; `bundle.py` for the single-file build.

**Storage**: Existing Google Sheets tables — `Submissions` (11 cols, per-question
review in `Detailed Review JSON`), `Question_Bank` (13 cols, Certified headers, incl.
`Subject`, `Unit / Topic`, `Points`, `Difficulty`), `Exams` (11 cols incl. `Exam
Type`, `Target Period`), `Sessions`, `Study_Plan`. **No new sheet** and **no schema
migration** required for this feature.

**Testing**: `npm test` (node unit/server tests with fake Sheets + Node VM,
incl. existing `normalizeAnswer.test.js`), Playwright E2E suite
(`python tests/e2e/run_all_e2e.py`, 51 scenarios), static button checks
(`python test_ui_buttons.py`).

**Target Platform**: Google Apps Script Web App (`ANYONE_ANONYMOUS` +
`USER_DEPLOYING`), browsers, Android kiosk via prebuilt `Index.bundle.html`.

**Performance Goals**: Mastery report renders in < 5 s at pilot scale (2 students,
hundreds of submission rows) with one batched read per involved sheet per report
render — no per-row read loops.

**Constraints**: Arabic labels RTL + NFKC-grouped keys (reuse `normalizeAnswer_`);
all privileged calls behind short-lived typed tokens; `Index.bundle.html` only ever
regenerated by `bundle.py`; single-build, single-quiz-runtime simplicity
(constitution Principle V).

**Scale/Scope**: Pilot family/small class; 2 students currently; 1 new student
screen (mastery view), 1 parent view extension on `pview-analytics`, 2 new server
RPCs, 1 new exam type (`Unit Practice`).
